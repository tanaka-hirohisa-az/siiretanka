# 仕入単価推移レポート 仕様書

作成日：2026-07-08
最終更新：2026-09-01（値上げ影響額タブの仕入実績ベースへの移行、先行検知タブの新設を反映）

## 1. 全体概要

### 1.1 目的

「仕入単価推移」レポートは、**納入品目**（お客様に納める完成品）と**材料**（その製造に使う原材料）の
2系統について、仕入単価の推移を月次で把握し、値上げ（または値下げ）を早期に検知し、その金額的な
影響を見積もることを目的とするレポートである。材料系のタブ群は、見積もった影響額を売価への転嫁
交渉の根拠として使うことも想定している。

### 1.2 データソース

Fabricデータウェアハウス（`dw_bee_genka-00001`）を単一のソースとする。レポート内の主な生テーブル
（インポート）は以下の通り。

| テーブル | 内容 |
|---|---|
| `TB_納入品目仕入先単価情報` | 納入品目×仕入先ごとの契約単価と適用開始日 |
| `TB_材料仕入先単価情報` | 材料×仕入先ごとの契約単価と適用開始日 |
| `TB_仕入実績情報` | 材料の実際の仕入実績（仕入日・数量・単価） |
| `TB_統合出荷情報` | 納入品目の出荷実績（稼働量算出に使用） |
| `TB_材料入出庫実績情報` | 材料の入出庫実績（稼働量算出に使用） |
| `納入品目情報` / `材料情報` | 納入品目／材料のマスタ情報 |
| `品目分類情報` | 分類マスタ（納入品目・材料で共有） |
| `tbl_calendar` | 日付ディメンション |

値上げ影響額タブと先行検知タブの2つだけは、Fabricデータウェアハウスを経由せず**社内システムの
データベースを直接参照**する。理由は、これらのタブが必要とする在庫場所（倉庫）と手配データが
データウェアハウス側に取り込まれていないためである。接続は Power Query のネイティブクエリで、
参照するテーブルは以下の通り。

| テーブル | 内容 | 使用タブ |
|---|---|---|
| `TB_仕入実績情報` | 材料の仕入計上明細（品目・仕入先・在庫場所・勘定年月・数量・金額） | 値上げ影響額 |
| `TB_材料手配残情報` | 材料の手配（発注）明細。完納済みも含む全履歴 | 先行検知 |
| `TB_材料情報` / `TB_品目分類情報` | 材料マスタと分類マスタ | 両タブ |
| `TB_仕入先情報` | 仕入先マスタ（仕入先名の付与） | 両タブ |

倉庫の分類は社内システムに持っていないため、`master/倉庫分類.csv` を手作業で作成しリポジトリに
置いている。倉庫番号ごとに仕向け先（BEI向けか国内向けか）を判定するために使う。

これらの生テーブルから、Power BI側の計算テーブル（DAXで生成される中間テーブル）が作られ、各タブの
ビジュアルはその計算テーブルを参照する。計算テーブルの生成ロジックはタブごとに異なり、これが
タブ間の数値の違いを生む最大の要因である（詳細は各タブの節を参照）。

| `b0c53a4cbd41c0616874` | 納入品目 | 納入品目 | 改定イベント単位 | 現行（この系統では唯一のタブ） |

| `a1b2c3d4e5f6789012ab` | 値上げ影響額 | 材料 | 月次・仕入実績ベース（前年最終月基準との差分） | 現行。No.5／No.6 に入れる数字を作る |
| `e1f2a3b4c5d60718293b` | 先行検知（手配ベース） | 材料 | 月次・手配ベース | 現行。単価変動の早期検知用。金額は参考値 |

値上げ影響額タブと先行検知タブは、同じ計算ルールを**仕入実績**と**手配**という別のデータに
当てたものである。両者を分けているのは、手配が単価変動を実績より早く捉える一方（2%超の変動を
両データが捉えた781組で、手配が先行60.6%・同月32.8%・遅行6.7%、中央値1か月先行）、金額としては
未完納分を含み計上月が実績とずれるためである。月次の影響額は最大60%ずれるので、`◎PLヒット案件
まとめ` に入れる数字は仕入実績ベースだけを使う。

「改定イベント単位」と「月次ベース」の違いは重要である。**改定イベント単位**（納入品目・材料(契約単価・変動)）は、
実際に契約単価が改定された日だけに1行が生成される方式で、月ごとの連続した水準の推移を追うことは
できない。**月次ベース**（材料(契約単価・月次)・材料(加重平均単価)・値上げ影響額・先行検知）は、材料×月の組み合わせで必ず（または条件付きで）1行を
持ち、改定がない月も含めて連続した推移を月次グラフで追える。

### 1.4 共通の仕組み

- **スライサー同期**：年・年月（階層）スライサーは、`tbl_calendar`の`年_yyyy年`/`年月_yy年MM月`を
  ソースとし、`syncGroup.groupName = "年月_yy年MM月"`によって**全タブ共通**で同期する。
  材料(加重平均単価)・材料(契約単価・月次)の2タブは、分類名・在庫材料番号・在庫場所のスライサーも
  同期グループ（それぞれ`分類名`・`在庫材料番号`・`在庫場所`）で相互に連動する。
  値上げ影響額タブと先行検知タブは、この2タブとはデータソースもテーブルも別系統のため、年月を
  除いて連動しない。代わりにこの2タブ同士が、仕向け区分・電線区分・部材区分の同期グループで
  連動する。納入品目タブ・材料(契約単価・変動)タブの品目番号／仕入先／分類名スライサーには同期
  グループが設定されておらず、**そのページ内でのみ**有効。
- **影響額の数量の考え方**：数量の取り方は2系統ある。納入品目・材料(契約単価)・材料(加重平均
  単価)の各タブは「単価差 × **直近12ヶ月の実績数量**」で、単発の改定が1年続いた場合の予測値を
  出す。値上げ影響額タブは「単価差 × **その月に実際に買った数量**」で、実際に発生した金額を出す。
  **前者は交渉判断のための見積り、後者は損益に計上する実績という違いがあり、タブをまたいで
  数値を単純比較してはならない。**
- **スライサーの既定選択**：既定選択は各スライサーの `visual.objects.general[].properties.filter`
  に保存される（`filterConfig` ではない）。**`filterConfig` に書くと視覚レベルフィルタとして
  働き、選択していない項目がスライサーの一覧から消えてしまう。**
- **タイトル表示**：材料系および値上げ影響額・先行検知の各タブは全チャートにカスタムタイトルを
  設定済み。納入品目・材料(契約単価・変動)タブは、カード以外のほとんどのビジュアルにカスタム
  タイトルが設定されておらず、Power BIの自動生成タイトル（列名を連結した表記）がそのまま表示
  される。

## 2. タブ別概要（利用想定）

### 2.1 納入品目タブ

お客様への納入品目について、仕入先との契約単価が改定されたタイミングを捉えるタブ。実際に
出荷があったかどうかとは関係なく、契約単価が変わった「その瞬間」の前後比較を一覧・グラフ化
する。用途：納入品目の値上げ改定の発生状況と、その1件ごとの影響額見積りの把握。

### 2.2 材料(契約単価・変動)タブ

材料版の「改定イベント単位」タブ。現在は**参照用としてのみ残置**されており、数値の正は
材料(加重平均単価)・材料(契約単価)の2タブである。新しいレポートを見る人は基本的に参照
不要。

### 2.3 材料(加重平均単価)タブ

材料の実際の仕入実績から算出した「実際に払っている単価」の月次推移を見るタブ。仕入があった
月だけで構成される。用途：実態としての値上がり状況の把握（実績指標）。

### 2.4 材料(契約単価・月次)タブ

仕入先との契約単価そのものの月次推移を見るタブ。実際の仕入の有無とは関係なく、契約改定を
毎月拾う。用途：先行指標としての建値の動きの把握。

### 2.5 値上げ影響額タブ

前年（2025年）の最終計上月の単価を基準に固定し、当年の各月についてその基準からいくら値上がり／
値下がりしたかを、その月に実際に買った数量で金額換算するタブ。用途：`◎PLヒット案件まとめ` の
No.5「BEE部材値上（電線）」と No.6「BEE部材値上（電線以外）」に入れる金額の作成と、その内訳の
確認。材料・仕入先・倉庫・月の単位まで下りて、どの材料をどの仕入先から買った分で、どの製品
ライン向けに値上げが起きたかを追える。

### 2.6 先行検知（手配ベース）タブ

値上げ影響額タブと同じ計算ルールを、仕入実績ではなく手配（発注）データに当てたタブ。用途：
単価変動を実績より早く見つけ、転嫁交渉の準備に使う。手配ベースの金額は未完納分を含み計上月も
実績とずれるため、金額そのものは参考値であり `◎PLヒット案件まとめ` には使わない。

## 3. タブ別詳細

### 3.1 納入品目タブ（ページID: `b0c53a4cbd41c0616874`）

#### データソースと生成ロジック

- 起点：`TB_納入品目仕入先単価情報`（納入品目×仕入先ごとの契約単価・適用開始日の生データ）
- `納入品目_仕入単価履歴`（計算テーブル）：上記を正規化し、品目×仕入先ごとに「前回単価」
  （直前に登録されていた契約単価）と「値上げ額」（今回単価－前回単価）を算出した履歴
- `納入品目_値上げイベント`（計算テーブル、**このタブの主データ**）：履歴のうち
  値上げ額が0でない行（＝実際に単価が変わった行）だけを残したもの。1行＝1回の改定
  イベント（品目×仕入先×改定日）
- `納入品目_月別純増減`（計算テーブル）：同一月内に複数回改定があった場合の、月初時点
  単価から月内最終単価までの正味の増減をまとめたもの（明細表の参考列にのみ使用）
- `納入品目_年平均稼働量`（計算テーブル）：`TB_統合出荷情報`から算出した直近12ヶ月・
  過去5年平均の出荷数量（影響額算出の数量根拠）

#### 主要項目定義

| 項目 | 定義 |
|---|---|
| 前回単価 | 同一品目×仕入先について、直前に登録されていた契約単価 |
| 値上げ額 | 今回の契約単価－前回単価（改定イベント1件ごとの単発の差分） |
| 値上げ率 | 値上げ額 ÷ 前回単価 |
| 改定方向 | 値上げ額>0なら「値上げ」、それ以外は「値下げ」 |
| 外れ値フラグ | 値上げ額の絶対値が5万円以上の改定に1を立てる（統計的な外れ値ではなく固定閾値） |
| 直近12か月稼働量 | 直近12ヶ月の実績出荷数量（`TB_統合出荷情報`ベース） |
| 年間予測影響額 | 値上げ額 × 直近12か月稼働量（この改定が今後1年続いた場合の影響額の見積り。実際に発生した累計コストではなく、単発の単価差を年間数量に掛けた予測値） |
| 年間予測影響額_値上げのみ／値下げのみ | 上記を値上げ・値下げで分けたもの |
| 月別_純増減額合計（明細のみ） | 同一月・同一品目内で複数回改定があった場合、月初時点単価から月内最終単価までの正味の増減額（`納入品目_月別純増減`から参照） |

### 3.3 材料(加重平均単価)タブ（ページID: `55cba7d188481af95d14`）

#### データソースと生成ロジック

計算テーブル`材料_加重平均単価_月次`（`TB_仕入実績情報`から生成）。材料×月ごとに、
当該月を含む直近6ヶ月の実仕入を合算して単価をならした「加重平均単価」を算出する。行が
存在するのは、その6ヶ月の間に実際の仕入が1件以上あった月のみ。

#### 主要項目定義

| 項目 | 定義 |
|---|---|
| 加重平均単価 | 当該月を含む直近6ヶ月の仕入金額合計 ÷ 仕入数量合計（1回の取引の単価ではなく、直近6ヶ月をならした値） |
| 前回加重平均単価 | 前月の加重平均単価。ただし前月を含む直近6ヶ月に仕入が1件もない場合は、直近で実際に仕入があった月の単月平均（その月の仕入金額÷仕入数）で代用 |
| 値上げ額 | 加重平均単価 － 前回加重平均単価 |
| 値上げ率 | 値上げ額 ÷ 前回加重平均単価 |
| 月内仕入数／月内仕入金額 | その月に実際にあった仕入のみの数量・金額（ローリング加算を含まない単月の実績値。仕入がない月はこの2列が空欄になる） |
| 直近12か月稼働量 | 直近12ヶ月の実績仕入数量の合計 |

### 3.5 値上げ影響額タブ（ページID: `a1b2c3d4e5f6789012ab`）

#### データソースと生成ロジック

社内システムの `TB_仕入実績情報` を Power Query のネイティブクエリで直接読み、テーブル
`仕入実績_影響額_月次` を作る。Fabricデータウェアハウスを経由しないのは、在庫場所（倉庫）が
データウェアハウス側に無く、仕向け先の判定ができないためである。

生成の順序は次の通り。

1. 材料×仕入先×**在庫場所**×勘定年月で数量と金額を集計する（2025年1月以降）。
2. そこから在庫場所を除いた材料×仕入先×勘定年月の単価を、分析関数で同じ1回のテーブル走査から
   求める。単価＝金額÷数量。**単価を材料×仕入先で求め、在庫場所は数量の分解軸としているのは、
   在庫場所を単価の粒度に含めると合計が変わってしまうためである。**この形なら仕向けを合算した
   ときに全体値へ厳密に戻り（Σ倉庫の数量＝その月の数量なので）、同時に仕向け別の内訳も取れる。
3. 材料×仕入先ごとに基準月を決める。2025年に計上があればその最終月、なければ2026年の初回計上月。
   どちらを使ったかは `基準区分` 列に残す。**基準が無い行を捨てず当年初回で代用しているのは、
   当年から取り扱いが始まった材料を落とすと影響額が過小になるためである。**
4. 在庫場所別の各行に基準単価と当月単価を結合し、影響額を計算する。

参照エクセル `BEE_材料_値上げ値下げ分析_2026.xlsx` の `計算方法` シートに書かれた定義と同一に
揃えてある。2026年1〜7月で、電線・電線以外それぞれの月別値上げ額・値下げ額、および仕入先別の
値上げ額が一致することを確認済み（12社すべて一致）。8月は参照エクセル側が期中スナップショットの
ため一致しない。

材料マスタは別テーブル `材料分類` として分離し、リレーションで結ぶ。**ファクト側のクエリに
マスタ結合を含めると Oracle 側で著しく遅くなったため**である。分離後はファクト10秒・マスタ6秒で
完了する。`材料分類` の主キーは、仕入実績と手配の両方に登場する材料番号の和集合から作る。
**手配側を含めないと、手配にしか無い546件が先行検知タブのスライサで空白として現れる。**
主キーは大文字小文字を無視し、前後の半角/全角スペース・タブ・改行を除去して一意化している。
**社内システムは大文字小文字を区別し末尾の全角スペースも保持するが、Power BI はこれらを同値と
扱うため、正規化しないと一対多リレーションシップの一の側に置けない。**

#### 主要項目定義

| 項目 | 定義 |
|---|---|
| 当月単価 | その月の計上金額 ÷ 計上数量。材料×仕入先で算出（在庫場所は含めない） |
| 基準単価 | 2025年の最終計上月の当月単価。2025年に計上が無ければ2026年の初回計上月の当月単価 |
| 基準区分 | 基準単価をどちらの規則で決めたか（前年最終月／当年初回） |

| 影響額_合計／値上げのみ／値下げのみ | 影響額の全体、値上がり分のみ、値下がり分のみ |

**除外条件を計算に埋め込まず `単価判定` と `部材区分` という列で持たせているのは、除外した中身を
画面上で確認できるようにするためである。**影響額の列には常に除外前の生の値が入っており、
スライサの選択だけで集計範囲が変わる。

`仕向け区分` は BEI 側の資料（`①BEE＆BEI_値上げ状況_収益性確認.xlsx` の `2_部材値上がり_BEI`）が

### 3.6 先行検知（手配ベース）タブ（ページID: `e1f2a3b4c5d60718293b`）

#### データソースと生成ロジック

社内システムの `TB_材料手配残情報` を直接読み、テーブル `手配_影響額_月次` を作る。このテーブルは
名前に「残」とあるが**未納分だけでなく完納済みも含む全履歴**（2002年以降64万件）であり、月次の
単価推移を追える。

値上げ影響額タブとの違いは3点ある。

1. 月の基準が `F_手配日`（発注日）であり、仕入実績の勘定年月（計上月）ではない。
2. 単価を据え置きで扱う。単価が変動した月の単価を、次の変動まで持ち越す。
3. 外貨建てを換算する。通貨は**仕入先番号の末尾**で判定し（D=USD、E=EUR、他=JPY）、`F_通貨コード`
   は使わない。**通貨コードは13,151件が空、377件のみ設定されており、値が入っていても誤っている
   例（`2050002E` が JPY）があるためである。**換算は単価差を外貨で取ってから、単価が変動した月の
   レート（`TB_外貨仕入実績情報` の当月レート）で円貨にする。**この順序にすると為替の動きが影響額に
   混ざらない。**外貨建ては手配額の約4.4%（USD 471,494ドル、EUR 7,454ユーロ）を占める。

#### 主要項目定義

| 項目 | 定義 |
|---|---|
| 通貨 | 仕入先番号の末尾から判定した通貨（JPY／USD／EUR） |
| 基準単価外貨／当月単価外貨／単価差外貨 | 各通貨建てのままの単価と差 |
| 適用レート | 単価が変動した月の当月レート。JPY は 1 |
| 単価変動月 | その単価がいつから効いているかを示す年月 |
| 月次数量 | 直近12か月の手配数 ÷ 12 |
| 影響額外貨／影響額円貨 | 単価差外貨 × 月次数量、およびその円貨換算 |
| 影響額_値上げのみ_手配／値下げのみ_手配 | 影響額円貨を値上がり・値下がりで分けたもの |
| PLヒット額_値上げ分_手配 | 影響額_値上げのみ_手配 の符号反転 |
| 影響額_値上げのみ_選択最終月_手配 | 選択している年月のうち最終月のみ。現在ビジュアル未使用 |

### 4.2 利用ガイド（Word）との役割分担

リポジトリ直下の `値上げ影響額_仕様書_ver1.0.docx` は、**レポートを開いて操作する人**向けの利用
ガイドである。サンプル `粗利確認_仕様書_ver1.2.docx` の構成に倣っている。この md は設計と定義を
記録する技術文書で、読み手が違う。

利用ガイドには、次の基準で**入れない**ものがある。利用者が画面の前で判断や操作をするために
必要のない情報だからである。

- 作り手側の事情（データの出どころ、更新の仕組み、設計判断の理由）
- 利用者が変更できないこと
- 他タブとの比較や、そのタブ以外の話
- 現時点の数値や検証結果（時間が経てば古くなる）

### 4.3 統合時に戻す内容

最終的には、レポート全体を対象とした1本の仕様書に統合する。**他タブとの比較は、そのときに必要に
なる**。現状はタブ5以外が陳腐化しているため統合の段階ではないが、統合時に使えるよう、いま把握
している内容をここに控えておく。

**影響額の数量の取り方が2系統ある。** 納入品目・材料(契約単価)・材料(加重平均単価)の各タブは
「単価差 × 直近12ヶ月の実績数量」で、単発の改定が1年続いた場合の予測値を出す。値上げ影響額タブは
「単価差 × その月に実際に買った数量」で、実際に発生した金額を出す。前者は交渉判断のための見積り、
後者は損益に計上する実績であり、タブをまたいで数値を単純比較してはならない。**利用者が他タブと
見比べて混乱する場面が実際にあるため、この点だけは利用ガイドにも残している。**

**基準の取り方も系統ごとに違う。** 改定イベント単位のタブは改定の前後比較、材料の月次タブは前月
比較または年度基準（前年12月）との比較、値上げ影響額タブは前年の最終計上月との比較である。

**データソースが2系統ある。** 大半のタブは Fabric データウェアハウス経由だが、値上げ影響額タブと
先行検知タブは社内システムを直接参照する。統合時には、この差が更新のタイミングや運用に影響するか
を確認する必要がある。**現時点でこのレポートがどう運用・更新されているか（サービスへの発行の
有無、定期更新の設定、社内システムへの接続がサービス側から通るか）は未確認である。**
